# Live full-scan benchmark, 22 November 2026

Read-only measurement of a real full scan (41 apps, 106 Homebrew packages,
107 developer packages, all sources and developer managers enabled) on an Apple
Silicon Mac with 15 cores, macOS 27.3.

Run: `UPKEEP_LIVE_SCAN_BENCHMARK=1 swift test -c release --filter liveScanBenchmark`
(`UPKEEP_LIVE_SCAN_RUNS` sets the number of full scans; default 3).

## Changes measured

- macOS: `softwareupdate --list` and `--list-full-installers` run concurrently;
  build details come from `SystemVersion.plist` instead of two `sw_vers` runs;
  automatic scans reuse a successful full-installer listing for up to 6 hours.
- npm, pnpm, Python and RubyGems run their inventory and outdated commands
  concurrently.
- VS Code extensions are checked with one batched marketplace query.

## Method

The old and new code were run alternately, three rounds of three full scans
each, after waiting for the 5-minute load average to fall below 8 (load 4–6
during the runs). The first scan in each process has cold network and tool
caches. Results depend on network and registry latency.

| | Old | New |
| --- | --- | --- |
| First scan in process (median of 3) | 3,672 ms | 2,607 ms |
| Later scans (median of 6) | 2,356 ms | 1,755 ms |

Every new-code run was faster than the old-code run in the same round. Raising
the local command limit from 8 to 12 did not help (RubyGems' `gem outdated`
sets the pace) and was not kept. An earlier set of runs taken while another
project's simulator tests held the load average near 97 was discarded.

## Follow-up: cached outdated results

RubyGems and npm now reuse their `outdated` result for up to 30 minutes while
the installed inventory output is byte-for-byte unchanged (the inventory is
still listed on every scan). In one process of four scans at load 5–6, the
first scan was 2,606 ms and later scans were 1,093, 1,582, and 990 ms; RubyGems
fell from about 1.4 s to 0.15–0.35 s and npm from about 1.1 s to 0.5 s. The
1,582 ms run was held by a slower `softwareupdate` response. Python's pip
checks (about 1 s) now set the pace of repeat scans.
